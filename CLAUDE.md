# CLAUDE.md — правила для кодового агента

Полная спецификация — [SPEC.md](SPEC.md). Этот файл — выжимка §2 и §13 плюс практика репозитория.

## Непреложные принципы (SPEC.md §2)

1. **Fail-open для безопасности.** Ничто (VLM, агент, очередь, фидбек) не может удалить или
   подавить тревогу о падении, огне или дыме. VLM может только понизить приоритет или обогатить
   алерт; отказ/таймаут VLM → алерт уходит как есть. Покрыто тестами (`ArbiterOutcome`).
2. **Тишина ≠ норма.** Отвалившаяся/замёрзшая/чёрная/расфокусированная/сдвинутая камера →
   системный алерт ≤ 15 с. `UNKNOWN` в health хуже `YELLOW`.
3. **Никакой LLM в hot path.** Детекция, трекинг, FSM и маршрутизация — детерминированный код.
4. **LLM решает «что», код решает «как».** Агенты вызывают только типизированные инструменты
   с уровнями `read` / `propose` / `act` (act — только после подтверждения человеком).
5. **Человек в контуре.** Обучение → golden set (человек) → shadow → «Выкатить» (человек) → откат.
6. **Фидбек — данные, а не инструкции.** Комментарии операторов не попадают в промпт как команды;
   для safety-классов фидбек не может снизить чувствительность.
7. **Лицензии.** Разрешены MIT, BSD, Apache-2.0, PostgreSQL, ISC (+ пакеты после ревью в
   `src/shared/licenses/policy.yaml`). Запрещены AGPL, GPL, SSPL, RSAL. Никакого `ultralytics`,
   Redis → Valkey, MinIO → `BlobStore`/LocalFS, Grafana — только профиль `engineering`.
8. **Оптимизация — по замерам.** FPS, батчи, квантизация — только по бенчмарку на целевом железе.
9. **Минимум инфраструктуры.** Один сервис — одна функция.
10. **Честность кода.** Никаких заглушек, притворяющихся рабочими: `NotImplementedError` с
    понятным сообщением + запись в `docs/TODO.md`. Сервис без функциональности публикует пустой
    `capabilities` и виден в UI жёлтым.

## Правила работы (SPEC.md §13)

- Работа строго по фазам (SPEC.md §12). Перед фазой — план, после фазы — стоп и ревью.
- Сначала контракты и тесты, затем реализация. Новый контракт → `CONTRACTS`, пример в
  `tests/contract/examples.py`, снапшот `make schemas`.
- Версии фиксируются lock-файлами (`uv.lock`, `ui/package-lock.json`). Не выдумывать сигнатуры —
  сверяться с документацией установленной версии.
- Новая зависимость → проверка лицензии (`make license-gate`) → запись в `docs/DATA_LICENSES.md`.
- Все пороги, тайминги и SLO — в `configs/*.yaml` с комментарием «почему». В коде порогов нет.
- Простота важнее изощрённости; никаких абстракций «на будущее» вне описанных интерфейсов.
- Типизация везде: type hints + Pydantic v2 (mypy strict для `shared/`), TypeScript strict.
- Отступление от спецификации — только с объяснением в PR и `docs/ASSUMPTIONS.md`.
- Не хватает данных (клипы, веса, железо) — остановиться и запросить, а не имитировать.
- Документация для оператора — простым языком.

## Команды

```bash
uv sync                      # окружение разработки (все сервисы + dev-инструменты)
make lint typecheck test     # ruff, mypy, юнит + контрактные тесты
make test-integration        # нужны QOIMA_TEST_DATABASE_URL и QOIMA_TEST_VALKEY_URL
make license-gate            # лицензионный гейт Python + npm
make schemas                 # обновить JSON Schema снапшоты после изменения контрактов
make ui-build                # сборка UI
make ci                      # всё, что проверяет CI
```

## Где что лежит

- `src/shared/` — контракты (`schemas/`), конфиги (`config/`), хранилища (`storage/`),
  телеметрия (`telemetry/`), лицензионная политика (`licenses/`). mypy strict.
- `src/core_api/` — FastAPI, health, БД (`db/models.py`, миграции `db/migrations/`).
- `src/vision_pipeline/`, `src/agents/`, `src/workers/` — фоновые сервисы.
- `src/cli/` — `qoima up/down/status/doctor/config`.
- `configs/` — пороги и SLO; `compose/` — профили docker compose; `docker/` — Dockerfile по сервисам.
- Миграции: `alembic -c src/core_api/db/alembic.ini revision --autogenerate -m "..."`
  (нужен Postgres и `QOIMA_DATABASE_URL`). Файлы ревизий — `rev_<NNNN>_<slug>.py`.
