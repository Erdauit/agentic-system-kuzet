# Промпты по фазам — машина с одной RTX 5070 Ti (16 ГБ)

Готовые промпты для Claude Code, которым работают прямо на машине с видеокартой: в Ubuntu
внутри WSL2 (стенд на Windows) или на Linux-сервере объекта. Один файл — одна фаза; поправки
под одну карту на 16 ГБ уже внутри.

## Как запускать

1. Claude Code ставится в Ubuntu, а не в Windows:

   ```bash
   curl -fsSL https://claude.ai/install.sh | bash
   ```

2. Для `git push` в конце фазы на машине нужен доступ к GitHub: `gh auth login` или SSH-ключ.
3. Обновите репозиторий и запустите промпт нужной фазы:

   ```bash
   cd ~/agentic-system-kuzet && git pull
   ```

   ```bash
   claude "$(cat docs/prompts/00-gpu-acceptance.md)"
   ```

Агент сначала показывает план и ждёт вашего «утверждаю». Потом делает фазу, проверяет её на этой
машине, коммитит и пушит в `main` и останавливается на ревью.

## Разрешения внутри промптов

Некоторые промпты прямо разрешают агенту скачать веса и образы. Если вы не согласны, удалите
эту строку из файла перед запуском:

- **00** — веса RF-DETR (Roboflow) и RTMPose (OpenMMLab);
- **04** — образы vLLM и SGLang, веса Qwen3-VL (4B, 8B в 4 битах, запасной вариант — 2B);
- **06** — модели эмбеддингов, детектор лиц;
- **07** — модели авторазметки и базовые веса для дообучения.

В каждом случае агент сначала проверяет лицензию. Если она не из разрешённых — останавливается и
спрашивает вас.

## Железо и бюджет видеопамяти

Одна RTX 5070 Ti: 16 ГБ видеопамяти, архитектура Blackwell (compute capability 12.0). Ей нужны
CUDA ≥ 12.8 и драйвер R580+; у нас CUDA 13. SPEC.md §4.1 рассчитан на карту с VLM от 24 ГБ —
здесь на 8 ГБ меньше.

Оценка до замеров (уточняется `qoima bench`):

| Кто занимает | ГБ | Комментарий |
|---|---|---|
| Рабочий стол Windows, если монитор подключён к 5070 Ti | 0,5–1,5 | на Linux-сервере без монитора ≈ 0; на стенде лучше подключить монитор к встроенной графике |
| Запас на фрагментацию и пики | ≈ 1 | сейчас в конфиге 2 ГБ — уточнить по замеру пиков |
| vision-pipeline: контекст CUDA, RF-DETR, RTMPose, дым и огонь (TensorRT FP16), декодеры NVDEC | 1,5–3 | растёт с числом камер и размером батча |
| Triton (Фаза 7) | 0,3–0,5 пустой, плюс модели | |
| Эмбеддинги (Фаза 6) | 0,3–1 | |
| VLM — всё, что осталось | 7–10 | |

Что из этого следует (заложено в промпты):

1. **VLM компактный.** Qwen3-VL-8B в FP8 из SPEC вместе с hot path не помещается: одни веса
   занимают ≈ 9–10 ГБ. Кандидаты: Qwen3-VL-4B-Instruct в FP8 (≈ 5 ГБ весов) и
   Qwen3-VL-8B-Instruct в 4 битах (≈ 6–7 ГБ), запасной — Qwen3-VL-2B. Модель выбирается замером:
   помещается ли, p95 ≤ 4 с, валидный JSON ≥ 95 %. Качество вердиктов проверяется в shadow.
2. **Жёсткие лимиты памяти.** Сейчас onnxruntime в пайплайне работает без лимита: его арена может
   разрастись и вытеснить VLM. Лимит пайплайна и `gpu_memory_utilization` для VLM считает
   планировщик, VLM стартует после пайплайна.
3. **Карта одна на всех — время делится.** Всплески нагрузки VLM могут замедлить hot path. Это
   меряется, и при нарушении SLO ограничивается VLM, а не детекция.
4. **Обучение и авторазметка — только в окне обслуживания, когда VLM выгружен.** В это время
   арбитр выключен: алерты уходят без арбитража (fail-open), и интерфейс это показывает.
5. **Каждая новая модель отнимает место у VLM.** Планировщик показывает этот размен, решает человек.
6. **Замеры со стенда на WSL — не для объекта.** Windows забирает часть видеопамяти, vLLM в WSL
   работает медленнее (без pinned memory). План для объекта считается по замерам на Linux.

## Место на диске

Сейчас система занимает ≈ 45 ГБ на пике. Сверх этого:

- **Фаза 4:** +25–35 ГБ — образы vLLM и SGLang и веса двух-трёх кандидатов VLM.
- **Фаза 6:** эмбеддинги и Qdrant — растут вместе с архивом.
- **Фаза 7:** образ для обучения с PyTorch (≈ 10–15 ГБ) и датасеты (десятки ГБ).

На стенде WSL для Фаз 4–7 держите не меньше 150 ГБ свободно на диске C:.

## Общие правила для агента (действуют в каждом промпте)

- CLAUDE.md и SPEC.md обязательны; этот файл — общий контекст про железо.
- Сначала план (файлы, интерфейсы, тесты, замеры), затем ждать подтверждения. После фазы — стоп.
- Цифры в плане и конфиге — только по замеру на этой машине. Оценки помечаются как оценки.
  Пороги — в `configs/*.yaml`, с комментарием «почему».
- Не хватает данных, весов, доступа или лицензия под вопросом — остановиться и спросить, а не
  имитировать.
- Отступление от SPEC.md записывается в `docs/ASSUMPTIONS.md`; новая зависимость проходит
  `make license-gate` и записывается в `docs/DATA_LICENSES.md`.
- На WSL каждый замер помечается: «стенд WSL, не для плана объекта».
- В конце фазы: `make ci`, интеграционные и e2e-тесты на этой машине; обновлены `docs/`,
  `CHANGELOG.md`, `docs/TODO.md`; коммит в `main` и push.
- Отчёт в конце: таблица замеров, что проверено, что не проверено, что нужно от человека.
