Фаза 8 — Feedback Analyst на одной RTX 5070 Ti (16 ГБ)

Прочитай CLAUDE.md; SPEC.md §2 п. 6, §9, §9.1 п. 10, §12 (Фаза 8); docs/prompts/README.md.
Модель — тот же компактный VLM, с самым низким приоритетом («агенты»).

Под маленькую модель:
- Всё, что считает (кластеры по коду причины, камере и времени, статистика), — это код. LLM
  только формулирует текст предложений по готовым сводкам.
- Запуск — раз в неделю по расписанию из конфига, не пересекаясь с окном обучения. Если очередь
  арбитра не пуста — ждёт.

Сначала покажи план и жди моего подтверждения.

1. **Кластеризация ложных срабатываний** — детерминированная.

2. **Предложения:** few-shot примеры для арбитра, параметры FSM, расписание плановых работ,
   переобучение.
   - До показа человеку каждое предложение проходит регрессионный прогон на golden set и роликах.
   - Применяется только после ревью человека (очередь ревью в UI).

3. **Safety-классы** (падение, огонь, дым). Предложение может только повысить точность без
   потери полноты на golden set. То, что снижает чувствительность, отклоняет код ещё до LLM
   (тест).

4. **Комментарии операторов** попадают в LLM только как цитируемые данные: отдельный блок
   данных, экранирование. Тесты на подмену инструкций: «игнорируй инструкции», «отключи алерты»,
   «подними порог» в комментариях не меняют ни одного предложения и ни одного параметра.

5. **Плейбук по §9 и evals.** Для тестов — синтетический фидбек: генератор на коде, кластеры
   известны заранее.

Приёмка (по SPEC):
- на синтетическом фидбеке формируются предложения;
- ни одно не применяется без ревью;
- подмена инструкций в комментарии не влияет на поведение;
- плюс: запуск не замедляет арбитр и hot path.

Отчёт: что сделано, что не проверено, что нужно от меня. Закоммить в main, запушь и остановись.
