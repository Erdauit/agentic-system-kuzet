# Руководство администратора

Для `site_admin` и инженеров Qoima: установка, запуск, подключение камер, диагностика (Фаза 1).

## Требования к серверу

| Что | Минимум | Проверяет |
|---|---|---|
| ОС | Linux, рекомендуется Ubuntu 22.04/24.04 LTS | `install.sh`, `qoima doctor` |
| GPU | 1–2 NVIDIA; для локального VLM — ≥ 24 ГБ VRAM на карте | `qoima doctor` |
| Драйвер NVIDIA | с поддержкой CUDA 13.x (ветка R580+) | `qoima doctor` |
| Docker Engine | ≥ 24.0 + плагин compose ≥ 2.20 | `install.sh`, `qoima doctor` |
| nvidia-container-toolkit | runtime `nvidia` зарегистрирован в Docker | `install.sh`, `qoima doctor` |
| Диск под данные | ≥ 200 ГБ свободно в `/var/lib/qoima` (рекомендуется SSD/NVMe 500 ГБ – 1 ТБ) | `qoima doctor` |
| Время | chrony, смещение ≤ 50 мс | `qoima doctor` |
| uv | для установки CLI | `install.sh` |

Пороговые значения — `configs/defaults.yaml`, раздел `doctor`. Стенд на Windows (WSL2) — см.
[WINDOWS.md](WINDOWS.md).

### Сколько места занимает система

Замерено на сборке 0.4.0; клипы и датасеты растут со временем.

| Что | Объём |
|---|---|
| Образы Qoima без GPU (core-api, vision-pipeline, agents, worker-gpu, media-base) | ≈ 2,3 ГБ |
| vision-pipeline-gpu (CUDA 13, cuDNN 9, TensorRT 10) | ≈ 6,3 ГБ |
| Triton 26.08 (GPU-профили) | ≈ 18 ГБ на диске (8,9 ГБ скачивается) |
| Прочие образы (Postgres, Valkey, Qdrant, MediaMTX, Prometheus) | ≈ 2 ГБ |
| Кэш сборки образов | 10–15 ГБ (освобождается `docker builder prune` после установки) |
| Модели и кэш движков TensorRT | 1–2 ГБ; веса VLM (Фаза 4) — ещё 10–20 ГБ |
| Подготовка RF-DETR (`tools/models`, один раз, torch) | 5–8 ГБ кэша uv — можно делать на другой машине |
| Клип инцидента (≈ 40 с mainstream ≈ 4 Мбит/с) + кадры | ≈ 20 МБ; 100 инцидентов в день × 30 дней ≈ 60 ГБ |
| Postgres, метрики Prometheus (30 дней) | единицы ГБ |
| Датасеты и обучение (Фазы 6–7, хранение 365 дней) | десятки–сотни ГБ |

Итог: установка с GPU-профилем занимает ≈ 45 ГБ на пике (во время сборки), дальше растут клипы,
датасеты и веса моделей — поэтому `qoima doctor` требует ≥ 200 ГБ свободно, а для объекта
рекомендуется отдельный NVMe на 500 ГБ – 1 ТБ под `/var/lib/qoima`.

## Установка

1. Скопируйте каталог поставки на сервер, например в `/opt/qoima`.
2. Запустите установку от root:

   ```bash
   sudo ./install.sh
   ```

   Скрипт проверит окружение, установит CLI `qoima` (`/usr/local/bin/qoima`), сгенерирует
   секреты и самоподписанный TLS-сертификат в `.secrets/`, создаст каталоги данных в
   `/var/lib/qoima`, соберёт образы и запустит `qoima doctor`. Повторный запуск безопасен:
   существующие секреты и данные не меняются.

   Другой каталог данных: `sudo ./install.sh --data-root /data/qoima`.

3. Запустите систему:

   ```bash
   qoima up
   ```

   CLI сам выберет профиль по числу GPU (1 GPU — всё на одной карте; 2 GPU — вторая карта
   отдаётся обучению) и дождётся, пока все сервисы станут healthy.

4. Откройте в браузере `https://<адрес-сервера>/`. Первый вход: логин `admin`, пароль — в
   файле `.secrets/admin_initial_password`; система попросит сменить его.
5. Мастер настройки → «3. Камеры»: введите логин и пароль камер (обычно одинаковые на объекте) и
   нажмите «Найти камеры». Система опросит сеть сервера (ONVIF и RTSP), покажет найденные
   устройства и подключит отмеченные одной кнопкой: сама найдёт основной и второй поток,
   снимет снапшот и базовую линию. Камеры в другом VLAN — укажите их подсети на шаге «1. Объект».
6. «7. Алерты»: Telegram (токен бота, chat id инженеров) и HTTP-реле; кнопка «Тест» проверяет канал.

> Офлайн-установка из подписанного бандла появится в Фазе 9. Сейчас установке нужен интернет.

## Ежедневные команды

| Команда | Что делает |
|---|---|
| `qoima status` | контейнеры и сводка «Состояние системы» |
| `qoima doctor` | полная самодиагностика с рекомендациями |
| `qoima down` | остановка (данные сохраняются) |
| `qoima up --engineering` | плюс Grafana для инженеров (только с самого сервера: `http://127.0.0.1:3000`) |
| `qoima config validate` | проверка `configs/` после правок |

## Настройка объекта

Основное настраивается в мастере (UI). Изменения сохраняются в `/var/lib/qoima/config/site.yaml`.
Не редактируйте `configs/defaults.yaml`; при ручной правке site.yaml указывайте только изменённые
значения, например:

```yaml
defaults:
  site:
    name: "Цех №3"
    shifts:
      - {name: "1 смена", start: "07:00", end: "15:00"}
      - {name: "2 смена", start: "15:00", end: "23:00"}
      - {name: "3 смена", start: "23:00", end: "07:00"}
```

После правки: `qoima config validate`, затем `qoima up`.

### Сценарии, зоны и участки (мастер, шаг 5)

1. Выберите камеру и отметьте сценарии: «Падение», «Опасная зона» (дым/огонь — когда будут веса
   модели).
2. «Зоны»: кликайте по углам на снимке камеры, введите название и тип:
   - **зона контроля** — где следить за падениями (без зон — весь кадр);
   - **опасная (красная) зона** — тревога, если человек стоит в ней дольше заданных секунд.
3. **Участок** — одинаковое имя у зон разных камер, которые смотрят на одно место (например,
   `press-3`). Тогда одно падение, замеченное двумя камерами, даст одну тревогу.
4. «Калибровка пола»: отметьте по порядку 4 угла прямоугольника на полу; если знаете расстояние
   между точками 1 и 2 — введите его в метрах.

Если камеру сдвинули (системный алерт «сдвинулся ракурс»), зоны перестают совпадать с картинкой —
снимите новую базовую линию (шаг 3) и проверьте зоны.

### Самотест (мастер, шаг 8) и канарейка

«Запустить самотест» создаёт тестовую тревогу на выбранных камерах: кадр и клип берутся с
камер по-настоящему, тревога с пометкой «САМОТЕСТ» уходит во все каналы (веб, Telegram, сирена).
Проверьте, что сообщения пришли, и нажмите «Алерты получены — подтвердить». В таблице видно время
до первого алерта (цель — ≤ 2 с) и статус доставки по каждому каналу.

Канарейка раз в 30 минут незаметно для операторов проверяет путь «камера → тревога» и поднимает
системный алерт, если путь сломан. «Проверить сейчас» запускает проверку вручную.

### План мощности (мастер, шаги 2 и 6)

Сколько камер и с каким FPS потянет этот сервер — считается только по замерам на нём самом.

1. На сервере запустите бенчмарк (несколько минут; распознавание при этом не останавливается):

   ```bash
   qoima bench
   ```

   Он измеряет декодирование видео (NVDEC и CPU) на ваших камерах, скорость моделей при разных
   батчах и — с `--vlm-url` — скорость VLM. Результат: `/var/lib/qoima/bench/bench-*.json`.
2. Шаг 2 мастера покажет итог по железу: «подходит / с ограничениями / не подходит» и почему.
3. Шаг 6 → «Пересчитать план»: FPS каждой камеры, загрузка, видеопамять, серая зона арбитра,
   предупреждения. Проверьте и нажмите «Применить план» — только после этого FPS камер меняется.
   «Скачать PDF» — отчёт для заказчика.
4. Если потом добавить камеры или включить сценарии, в мастере и в «Состоянии системы» появится
   жёлтая плашка: план пересчитан и, если нужно, предложено понизить FPS отдельных камер. Сама
   система ничего не понижает — примените новый план на шаге 6.

После замены видеокарты, драйвера или обновления Qoima запустите `qoima bench` заново.

### Модели распознавания

Без моделей система работает (камеры, буфер видео, клипы, самотест), но не распознаёт людей —
«Состояние системы» показывает это у vision-pipeline. Модели готовит инженер Qoima
(`tools/models/README.md`) и кладёт в `/var/lib/qoima/models/registry/`.

## Где что лежит

| Путь | Содержимое |
|---|---|
| `.secrets/` | пароли Postgres, Valkey, первого входа admin, TLS-сертификат (каталог 700). Не копируйте в чаты и тикеты |
| `.secrets/runtime/` | пароли камер и токен бота, введённые в мастере (читает только core-api) |
| `/var/lib/qoima/config/site.yaml` | настройки объекта из мастера |
| `/var/lib/qoima/doctor/report.json` | последний отчёт `qoima doctor --report` (таймер раз в 5 мин) |
| `/var/lib/qoima/postgres` | база данных |
| `/var/lib/qoima/{clips,frames,datasets,models}` | клипы, кадры, датасеты, модели |
| `/var/lib/qoima/prometheus` | метрики (30 дней) |
| `configs/` | конфигурация |

Логи сервисов: `docker compose -p qoima logs <сервис>` (JSON, ротация 5 × 50 МБ).

## Типовые проблемы

| Симптом | Что делать |
|---|---|
| `qoima doctor`: «runtime nvidia не зарегистрирован» | `sudo nvidia-ctk runtime configure --runtime=docker && sudo systemctl restart docker` |
| «драйвер поддерживает CUDA 12.x» | обновить драйвер NVIDIA до ветки R580+ |
| «права каталога .secrets» | `chmod 700 .secrets` |
| `qoima up` не дождался healthy | `qoima status`, затем `docker compose -p qoima logs <сервис>` |
| В UI «Время: нет данных» | нет свежего отчёта doctor: `systemctl status qoima-doctor.timer`, вручную — `qoima doctor --report` |
| Поиск не нашёл камеры | камеры в другом VLAN — добавьте подсети на шаге 1; проверьте логин/пароль; добавьте камеру вручную по RTSP |
| Забыт пароль | `qoima user reset-password <логин>` — выдаст временный |

Резервное копирование (`qoima backup` / `restore`) и обновления (`qoima update`) — Фаза 9.
