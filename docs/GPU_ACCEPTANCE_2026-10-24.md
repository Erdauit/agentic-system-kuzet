## Доступ и расположение

- Ubuntu: `Ubuntu-24.04`; проект `/root/agentic-system-kuzet`; данные `/var/lib/qoima`.
- Логин `admin`; случайный пароль в `.secrets/e2e_admin_password` внутри Linux-проекта.
  Из Windows: `\\wsl.localhost\Ubuntu-24.04\root\agentic-system-kuzet\.secrets\e2e_admin_password`.
  Начальный пароль сменён при e2e-проверке авторизации.
- Запуск из PowerShell: `wsl -d Ubuntu-24.04 -u root -- qoima up`.
  Локальная оболочка `qoima` использует порт 19443: 443, 8443 и 9443 заняты другими приложениями.

  не удалялись. Docker Desktop для стенда не требуется.
- API проверяется с закреплённым `.secrets/tls.crt`, без отключения проверки TLS.
  Визуальная проверка браузера остановлена на самоподписанном сертификате: предупреждение
  должен подтвердить пользователь. WHEP-сигнализация проверена через API.
- Таймер `qoima-doctor` активен. Автозапуск стенда при входе в Windows не настроен;
  текущую сессию WSL удерживает скрытый процесс. После перезагрузки Windows нужен запуск стенда.

## Изменения и проверки

- Добавлены настройки памяти на ONNX-сессию: `cuda_arena_limit_mb`,
  `cuda_arena_extend_strategy`, `trt_workspace_mb`. Они передаются обеим моделям и бенчмарку;
  кэш TensorRT разделён по размеру workspace. Числовые пределы остаются `null` до замеров,
  стратегия роста — `kSameAsRequested`. CUDA ограничивает арену, TRT — рабочую область;
  это не общий предел памяти процесса. Имена опций сверены с исходниками ORT 1.31:
  [CUDA](https://github.com/microsoft/onnxruntime/blob/v1.31.0/onnxruntime/core/providers/cuda/cuda_execution_provider_info.cc),
  [TRT](https://github.com/microsoft/onnxruntime/blob/v1.31.0/onnxruntime/core/providers/tensorrt/tensorrt_execution_provider_info.cc).
- VRAM измеряется во время загрузки модели и каждого батча с интервалом из конфига
  (по умолчанию 0,01 с). Это выборочный пик всей карты относительно исходного фона;
  короткие всплески могут быть пропущены. Ошибка NVML или падение ниже фона дают `null`
  и предупреждение; CPU не получает замер GPU. Фон Windows влияет на результат.
- Исправлено чтение заголовка `CUDA UMD Version` в doctor и отпечатке бенчмарка.
- Установщик создаёт `bench/` с владельцем 10001:10001. До исправления e2e обнаружил
  PermissionError при сохранении результата. Добавлены два регрессионных теста.
- Экспорт RF-DETR получает версию из `importlib.metadata`: у rfdetr 1.11.2 нет `__version__`.
- E2E умеет находить симулятор по IP и Docker DNS-имени; оба случая покрыты тестами.
- Итоговый `make ci`: **406 passed, без пропусков**, Ruff — 199 файлов, mypy — 152 файла,
  TypeScript, лицензии и все профили Compose прошли. Сборка UI и `bash -n install.sh` прошли.
- **13 интеграционных тестов прошли** на отдельных временных PostgreSQL/Valkey.
- GPU-e2e: **9 passed, 1 skipped** (автопоиск уже прошёл отдельно). Проверены WHEP,
  отключение камеры в пределах SLO, замерший и размытый кадр, клип MP4, WebSocket-алерт,
  локальные подмены Telegram/реле, повторная доставка после отказа, канарейка, PDF и применение
  плана. После перехода на DNS отдельно повторены живое видео и отказ камеры: **2 passed**.
- Применён тестовый CPU-план `fits_with_limitations` без распределения моделей.
  Это проверка механизма планирования; ёмкость RTX 5070 Ti по нему определять нельзя.

## Особенности настройки стенда

При настройке таймера `systemctl daemon-reload` лишил уже запущенные GPU-контейнеры доступа
к NVML. Health стал красным, e2e обнаружил отказ. После перезапуска трёх GPU-контейнеров
NVML и e2e восстановились. Это соответствует [известной проблеме NVIDIA](https://docs.nvidia.com/datacenter/cloud-native/container-toolkit/latest/troubleshooting.html).

Завершающие шаги установки выполнены отдельно: копирование исправленного `install.sh`
во время первой сборки прервало чтение работающего скрипта после сборки образов.
Полный повтор установщика не выполнялся; исправленный шаг создания каталогов проверен тестами.

После перезапуска Docker внутренние IP симуляторов изменились. Только четыре тестовые камеры
переведены на `qoima-camera-sim-1` … `qoima-camera-sim-4`. Сохранены история и идентификаторы,
добавлен аудит, исходные адреса записаны в `/var/lib/qoima/config/sim-addresses-before-20261024.json`.
Смена адресов выполнена обслуживанием данных стенда: API пока не позволяет редактировать URL
существующей камеры. Новый автопоиск по-прежнему возвращает IP, автоматический перевод в DNS
не реализован.

Временный кэш сборки удалён (Docker: 32,31 ГБ). Уплотнение VHD не завершилось: файл удерживается
WSL; общий останов WSL отклонён автоматической проверкой разрешений и ожидает решения пользователя.
Стенд восстановлен адресным перезапуском Ubuntu, все контейнеры healthy. Физический диск C:
остаётся ниже порога; большой виртуальный свободный объём внутри Linux не заменяет место Windows.
