# Не реализовано (по фазам)

Каждый пункт здесь — то, что в коде явно помечено как «не реализовано» (`NotImplementedError`,
пустой `capabilities`, статус `not_deployed` в health). Ничего из этого не имитируется.

## Фаза 1 — сделано, остались хвосты

  картинка в браузере на macOS/Docker Desktop не пошла из-за UDP-NAT Docker Desktop; визуально
  проверить на Linux-сервере объекта.
- Тексты проверок и алертов приходят с сервера только на русском — локализация kk.
- Привязка к реальным камерам: шаблоны URL производителей (`verified: false`) и ONVIF проверены
  только на симуляторе — подтвердить на камерах объекта.
- Мастер, шаг 1: редактор графика смен — текстовый; удобный редактор — Фаза 9.

## Фаза 2 — сделано без данных; приёмка по падению и дыму ждёт данных
Ждём от команды (SPEC.md §13.9 — не имитируем):
- **Тестовые ролики** `samples/e2e/` (постановочное падение, дым, проход в красную зону) — для
  приёмки FallFSM/SmokeFireFSM на видео, подбора порогов `configs/scenarios/*.yaml` и канарейки
  с прогоном ролика через модели (`qoima sim play <N> e2e/fall_staged.mp4` уже работает).
- **Веса**: RF-DETR (`tools/models/prepare_rfdetr.py` — скачивает веса Roboflow, нужен ваш
  запуск/согласие) и RTMPose (`tools/models/register_onnx.py` + шаблон `models/registry/rtmpose-body.yaml`);
  веса дыма/огня Qoima. Без них vision-pipeline не объявляет `person_detection`/`fall`/`red_zone`,
  а дым/огонь — «не развёрнуто».
- **GPU**: образ vision-pipeline сейчас с onnxruntime (CPU). Вариант с onnxruntime-gpu
  (TensorRT EP, FP16, кэш движков `models/engines/<gpu>-drv<версия>-ort<версия>/`) и NVDEC
  собрать и проверить на целевом сервере.

Осталось по коду:
- Выбор модели позы RTMPose vs RF-DETR keypoints — бенчмарк точности/скорости на роликах.
  RTMPose: подаём RGB (mmpose обучает с bgr_to_rgb), rtmlib подаёт BGR — сверить на бенчмарке.
- FallFSM: угол корпуса считается от вертикали кадра; угол относительно плоскости пола через
  гомографию — после роликов (гомография уже считается и публикуется в реестр камер).
- SmokeFireFSM: рост площади кандидата есть; «движение по оптическому потоку» — вместе с моделью.
- Мастер, шаг 5: редактор расписания плановых работ зоны (сварка, пропарка) — сейчас только API.
- Канал OPC UA — доставка честно завершается ошибкой «не реализован»; используйте реле.
- Повторный автопоиск должен обновлять адрес камеры, сменившей IP (DHCP), по серийному номеру
  ONVIF — сейчас такая камера уходит в «нет потока» (системный алерт) до переподключения вручную.
- Тексты алертов на kk и подписи UI — вычитка носителем.
- Эскалация до сирены проверена интеграционным тестом (БД, Modbus-сервер pymodbus), но не e2e:
  служебные события (самотест) не эскалируют, а настоящих событий без моделей нет.

## Стенд на Windows (WSL2)
- 2026-10-24: установлены Ubuntu 24.04, Docker Engine и NVIDIA Container Toolkit на RTX 5070 Ti;
  GPU виден из контейнера, NVDEC H.264 проверен на 720p и 360p. После загрузки образов
  `qoima doctor` показывает FAIL: на диске Windows осталось меньше обязательных 80 ГиБ.
  Исправлено чтение `CUDA UMD Version` драйвера 610.88. Подробности и оставшиеся проверки:
  [отчёт GPU-приёмки](GPU_ACCEPTANCE_2026-10-24.md).
- GPU-приёмка не завершена: нужны TensorRT на реальных моделях, два бенчмарка, проверка
  памяти под нагрузкой и план мощности. Числовые лимиты CUDA/TRT ещё не выбраны по измерениям.
- Лицензии данных RTMPose Body7 требуют решения владельца. Существующий симулятор и
  синтетический бенчмарк генерируют H.264; для проверки H.265 нужен соответствующий поток
  или разрешённый тестовый образец.
- Четыре симулятора найдены и подключены; GPU-e2e камер, тревог и планировщика прошли
  после исправления каталога `bench/` и восстановления NVML после `systemctl daemon-reload`.
  TensorRT FP16 проверен на диагностическом графе `sm120`; реальные модели ещё не проверены.
  После перезапуска Docker адреса симуляторов изменились: стенд переведён на постоянные DNS-имена.
  Автоматическое обновление адреса камеры после нового автопоиска и редактирование её URL через
  API пока не реализованы. Видеосигнализация WHEP проверена;
  визуальный live-просмотр в браузере и автозапуск через планировщик Windows ещё не проверены.
